IMPLEMENTATION CONTRACT
- `CredentialHealthScheduler` persists one versioned atomic JSON document with independent `sub2api_401` and `chatgpt2api_401` records.
- The scheduler uses a process singleton keyed by the resolved state path, one coordinator, a two-slot executor, and one active future per job.
- Persisted `running`/`waiting_for_queue` state becomes `interrupted` after restart and is due once if enabled.
- Configuration validates literal booleans and integer intervals 5..1440; enabling sets immediate due time; completion sets the next due time.
- Manual Sub2API retry and ChatGPT2API queue ownership cause the automatic round to return `skipped_busy`; no duplicate work starts.
- State, audit, logs, and API responses contain only bounded operational metadata, never AT, RT, management keys, OAuth codes, cookies, authorization headers, or credential payloads.
- Docker maps `/app/credential_health_scheduler.json` to `/data/credential_health_scheduler.json`.
