Changed contracts
-----------------
-  sends exact encoded ID requests in
  strict order: PUT /api/v1/admin/accounts/:id with {"status":"inactive"}, then DELETE.
- DELETE is not sent if deactivation fails; deactivation and deletion failures are
  sanitized and persisted as retryable cleanup evidence without secrets.
-  requires exact locked old ID, deterministic keeper,
  unchanged snapshots, full same-email group refresh, and explicit confirmation.
- A request failure plus a concurrent old-ID disappearance is not falsely reported as
  cleaned. A later reconciliation may mark it cleaned only after pre-call absence is
  independently verified, without another destructive request.
- Historical keeper rules remain: single healthy, unique latest healthy, or unique
  latest account only when every account is definitively unauthorized. Ambiguous,
  timeout, unknown, tied, missing, or invalid timestamps cannot be deleted.
- Normal OAuth replacement cleanup still requires a unique healthy new account_id.
- Future retry runner auto-cleans only selected same-batch cleanup_ready old IDs.
- API and template retry concurrency default to 3.
